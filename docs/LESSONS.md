# 经验记录 · LESSONS

> 用途：记录“试过但放弃”的方案及原因，避免重复踩坑。
> 何时查阅：准备改动 auto-hide / 探头条 / 窗口区域逻辑之前。
> 更新规则：出现新的放弃方案或同类问题重复 2 次时追加一条。

---

## L1 · 动画中途替换区域

- **尝试**：任务栏滑动过程中把“探头条 + 分段”换成正常分段区域，期望线条随分段到位而消失。
- **结果**：Windows 直接把任务栏跳到最终位置，动画中断（实测 top=1071 → 瞬间 1032）。
- **结论**：动画期间只能保持区域不变。已写入 `CLAUDE.md` 禁区。

## L2 · 动画结束时立刻撤线

- **尝试**：滑动期间 15 ms 轮询，动画停止的下一 tick 应用不带探头条的区域（`28866a4`）。
- **结果**：功能可用，但与原有 100 ms 轮询相比视觉差异很小，用户判定“无实质作用”，已 revert（`ab226cb`）。
- **结论**：不要为几十毫秒的观感差异增加轮询频率。

## L3 · 用 ABM_SETSTATE 做“看门狗”

- **尝试**：检测到任务栏完全移出屏幕或卡在滑动状态超过 2 秒，就切换 `AlwaysOnTop` → `AutoHide`（等同开关系统设置）自愈。
- **结果**：会触发布局重算、改变工作区，最大化窗口尺寸随之变化，影响日常使用。
- **结论**：已删除看门狗及启动时的一次性恢复。窗口尺寸稳定性优先于自动自愈。

## L4 · 全宽探头条

- **尝试**：隐藏态在屏幕边缘保留整条 2 px 线，任何位置都能触发。
- **结果**：未启用分段的空白区域也会出现线条，弹出时观感差。
- **结论**：改为只覆盖实际可能出现的分段范围（`2a4bf6d`）；全部分段都关闭时才退回全宽。

## L5 · 隐藏时把 alpha 设为 1 以隐藏线条

- **尝试**：`SetLayeredWindowAttributes` 把隐藏态任务栏整体调至 alpha=1。
- **结果**：实测可命中、可正常弹出，但强杀进程后任务栏会停留在近透明状态。
- **结论**：未采用。除非愿意承担恢复风险，不要再走这个方向。

## L6 · 5 秒轮询对齐自动隐藏状态

- **尝试**：后台每 5 秒读一次 `StuckRects3` 并通过 `Dispatcher.Invoke` 调用 `AutoHide`。
- **结果**：能兜底长时运行失效，但持续性开销不符合“减少资源占用”的要求。
- **结论**：改为系统事件驱动（`2edc96f`）。

## L7 · 上游自绘 alpha 自动隐藏

- **背景**：上游隐藏/显示由 RoundedTB 自己控制，不依赖屏幕边缘可命中像素，因此 top margin / 圆角不会影响触发。
- **结果**：会改写工作区，导致窗口尺寸问题，fork 已替换为原生 appbar 自动隐藏（`dbcdb1f`）。
- **结论**：如果要彻底摆脱探头条，只能恢复“自管隐藏”方向，需同时解决工作区问题。

## L8 · 把 Raw Input 坐标当作长期缓存

- **尝试**：`WM_INPUT` 到达时缓存光标坐标，后续每个 tick 复用缓存，只在没有缓存时读 `GetCursorPos`。
- **结果**：High integrity 前台窗口聚焦时 Raw Input 可能停止送达，缓存坐标永久过期，悬停触发“几乎不工作”；普通前台窗口下又看似正常。
- **结论**：Raw Input 只当触发信号，位置每次用 `GetCursorPos` 读取（D13）。不要用时间戳/新鲜度策略给缓存续命，实时读取更简单。
